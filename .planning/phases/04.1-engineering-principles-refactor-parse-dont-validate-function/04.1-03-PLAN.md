<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub API JSON → mapGitHubIssue/mapGitHubPR | Raw external API response (any shape) enters typed domain space |
| GitHub OAuth JSON → oauthTokenResponseSchema | GitHub OAuth token response (untrusted external) enters domain space |
| GitHub user JSON → gitHubUserSchema | GitHub user API response (untrusted external) enters domain space |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-03-01 | Tampering | mapGitHubIssue(issue: any) — unsafe field access | mitigate | Replace `any` parameter with `unknown`; call `gitHubApiIssueSchema.parse(rawIssue)` before field access — ZodError surfaces as 500 immediately |
| T-04.1-03-02 | Tampering | mapGitHubPR(pr: any) — unsafe field access | mitigate | Same — replace `any` with `unknown`; call `gitHubApiPRSchema.parse(rawPr)` |
| T-04.1-03-03 | Spoofing | OAuth callback — tokenData.access_token accessed without schema validation | mitigate | oauthTokenResponseSchema.parse() replaces unvalidated await .json() field access; covered in Plan 04 callback refactor |
| T-04.1-03-04 | Information Disclosure | GitHub API error responses — unexpected fields silently ignored | accept | Zod schemas use `.default([])` for array fields and `.optional()` for nullable fields; unknown top-level fields are passed through (no .strict()) — acceptable for GitHub API evolution |
</threat_model>
