## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`gap-1`, `px-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `px-2`, `py-2`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`) |
| lg | 24px | Section padding inside panels (`p-6`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- `IssueListRow` row height is 44px (`h-11`) — existing touch target; maintain for triage badge slot
- Triage control row inside `IssueDetailPanel`: 32px height (`h-8`) compact buttons/controls to keep the triage section visually subordinate to the issue title
- Priority pill in list row: 20px height (`h-5`) to align with existing assignee avatar height

Source: existing `IssueListRow` (`h-11`), `IssueDetailPanel` (`p-6 space-y-4`), button sizes (`h-8` = `size="sm"`)

Priority color semantics (applied via inline Tailwind utility classes, not new CSS variables):

| Priority | Color token | Light hex | Dark hex | Tailwind class pattern |
|----------|------------|-----------|----------|------------------------|

## Component Inventory

All new UI elements in this phase. Every component reuses existing Radix UI primitives and the `cn()` pattern from the codebase.

### 1. TriageSection (new — inside `IssueDetailPanel`)

Position: Inserted between the issue header block and the meta section in `IssueDetailPanel`. Always visible when the panel is open.

Structure:
```
[ClosedIssueWarning?]          ← conditional, shown when issue.state === 'closed'
[TriagedToggle] [PrioritySelector]   ← compact horizontal row, h-8
[divider]                      ← border-t border-border (matches existing divider)
```

- Container: `flex items-center gap-3` with `py-2` vertical padding
- Sits above the existing meta section; a `border-t border-border` divider separates TriageSection from the meta block below

### 2. TriagedToggle (new — inside TriageSection)

A compact toggle button (not a checkbox) indicating triaged state.

- Untriaged state: `Button variant="outline" size="sm"` with `CheckCircle` lucide icon (unfilled / `text-muted-foreground`)
- Triaged state: `Button variant="outline" size="sm"` with `CheckCircle2` lucide icon (`text-success`) + `border-success/30` border tint
- Label text: `"Mark as triaged"` (untriaged) / `"Triaged"` (triaged) — 12px
- Loading state: `disabled` + `opacity-50` during optimistic mutation
- Aria: `aria-pressed={isTriaged}` — toggle semantics

### 3. PrioritySelector (new — inside TriageSection)

Use Radix UI `DropdownMenu` (not `Select`) — consistent with existing `dropdown-menu.tsx` usage in the project and cleaner trigger presentation.

- Trigger: `Button variant="outline" size="sm"` showing `"Priority: {label} ▾"` or `"Priority: None ▾"` when unset
- Dropdown items: Critical, High, Medium, Low, then a separator, then "Clear"
- Each item shows a 6px colored dot + label text (12px)
- Active/selected item: `font-semibold` + matching priority color on the dot
- "Clear" item: removes priority (sets to null); shown only when priority is currently set
- Aria: `aria-label="Set priority"` on trigger

### 4. ClosedIssueWarning (new — inside TriageSection, conditional)

Shown when `issue.state === 'closed'`. Inline banner, not a modal.

- Appearance: `rounded-md border border-warning/30 bg-warning-light px-3 py-2` with `AlertTriangle` lucide icon (16px, `text-warning`)
- Text: 12px, `text-muted-foreground`
- Placed above the toggle/priority row within TriageSection

### 5. TriageBadgeSlot (new — inside `IssueListRow`, rightmost slot)

Added after the `productBadge` slot in `IssueListRow`. Renders only when `triageState` prop is provided and not empty.

- Priority-only (no triaged): `[High]` pill — `Badge` using priority color variant pattern
- Triaged-only (no priority): `CheckCircle2` icon, 14px, `text-success`
- Both triaged + priority: `[High]` pill + `CheckCircle2` icon in a `flex gap-1` container
- Neither: renders nothing (no DOM node)
- Prop: `triageState?: { isTriaged: boolean; priority: 'critical' | 'high' | 'medium' | 'low' | null }` — optional; follows `productBadge` optional prop precedent

Source: CONTEXT.md D-03, D-04

## Interaction Contract

### Keyboard Navigation (TRIAGE-05)

- `j` key: move to next issue in the visible list AND update the detail panel to show that issue
- `k` key: move to previous issue in the visible list AND update the detail panel to show that issue
- Active only when detail panel is open (`isOpen === true`)
- When panel is closed, `j`/`k` do nothing
- Implementation: `useEffect` + `window.addEventListener('keydown', ...)` — matches existing patterns
- At list boundaries: `j` on the last issue does nothing; `k` on the first issue does nothing
- Focus is NOT moved to the panel on `j`/`k` — selection changes, panel content re-renders

Source: CONTEXT.md D-05

### Optimistic Updates (TRIAGE-03, D-08)

- Triage toggle and priority dropdown update instantly in the UI before the API call resolves
- Implementation: TanStack Query v5 `useMutation` with `onMutate` → `queryClient.setQueryData()` optimistic update and `onError` rollback
- On rollback: toast error is shown (use existing `ToastContainer` component)
- Query key: `['triage', owner, repo, number]`

### Triage State Loading (D-07)

- Fetch fires when `IssueDetailPanel` `issue` prop changes (panel opens for a new issue)
- `useQuery({ queryKey: ['triage', owner, repo, number], queryFn: ... })`
- Loading state: triage controls render with `opacity-50 pointer-events-none` skeleton treatment
- No eager batch fetch for all list items

## Accessibility Contract

- `TriagedToggle`: `aria-pressed` on the button element; `aria-label` from `issues:triage.triagedAriaLabel`
- `PrioritySelector`: trigger uses `aria-label` from `issues:triage.priorityAriaLabel`; Radix DropdownMenu handles `role="menu"` / `role="menuitem"` natively
- `ClosedIssueWarning`: `role="alert"` on the banner container so screen readers announce it when it appears
- Keyboard shortcuts `j`/`k`: do NOT hijack focus from form elements; guard with `event.target.tagName !== 'INPUT' && event.target.tagName !== 'TEXTAREA'`
- Priority color pills: never convey information by color alone — always show the priority label text alongside the color dot
