## Spacing Scale

Declared values (multiples of 4 only). This phase inherits the project-wide scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (gap-1), label dot gap |
| sm | 8px | Compact inline padding, button internal gap |
| md | 16px | Row horizontal padding (px-4), filter bar padding |
| lg | 24px | Empty state internal spacing (space-y-3 → gap-6) |
| xl | 32px | Empty state outer padding (p-8) |
| 2xl | 48px | Major section breaks (not used in this phase) |
| 3xl | 64px | Page-level (not used in this phase) |

Exceptions:
- Issue row height: `h-11` (44px) — touch-target minimum, unchanged from Phase 2
- Sidebar width: `w-56` (224px) expanded, `w-14` (56px) collapsed — unchanged from existing Sidebar
- Product color dot in row: `h-2 w-2` (8px) — same as label dots and sidebar product dots
- Product badge text label: `px-2 py-0` — matches existing state Badge sizing
- Error banner stacking: `space-y-2` (8px) between multiple per-repo banners

**Source:** `IssueListRow.tsx`, `IssueSkeletonRow.tsx`, `Sidebar.tsx`, CONTEXT.md D-12

## Typography

All sizes declared in Tailwind utility classes (`text-[Npx]`, `text-xs`, `text-sm`).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 (normal) | 1.5 | Issue title in row, banner body text |
| Label / Caption | 11px (`text-[11px]`) | 400 (normal) | 1 | Issue number, state badge text, product name in badge |
| Heading | 14px (`text-sm`) | 500 (`font-medium`) | 1.2 | Empty state heading, error state heading |
| Section label | 12px (`text-xs`) | 500 (`font-medium`) | 1 | Sidebar section headers (uppercase + tracking-wider) |

Two weights in use: `font-normal` (400) and `font-medium` (500). `font-semibold` (600) reserved for active nav items only — do not introduce additional weights in this phase.

**Source:** `IssueListRow.tsx` (title `text-sm font-normal`, number `text-[11px]`), `IssuesView.tsx` (error heading `text-sm font-medium`), `Sidebar.tsx` (section label `text-xs font-medium uppercase tracking-wider`)

## Component Inventory

New components introduced in this phase:

### AllIssuesView (`src/client/components/AllIssuesView.tsx`)
- Layout: `flex flex-col h-full overflow-hidden` — matches `IssuesView.tsx` shell
- Filter bar: simplified version of `IssuesFilterBar` with state toggle + search only (no labels/assignee dropdowns)
- Issue list pane: `flex-1 flex flex-col overflow-y-auto`
- Detail panel: reuse `IssueDetailPanel` as-is
- **Visual hierarchy:** The issue list pane (`flex-1`) is the primary focal point of the page — it occupies the dominant portion of the viewport and is the main content anchor. All other UI elements (filter bar, error banners, detail panel) are secondary to it.

### ProductBadge (inline within `IssueListRow` extension or wrapper)
- Colored dot: `h-2 w-2 rounded-full flex-shrink-0` with `style={{ backgroundColor: product.color }}`
- Product name: `text-[11px] text-muted-foreground truncate max-w-[80px]`
- Container: `flex items-center gap-1 flex-shrink-0`
- Position in row: after the state badge, at the far right — rightmost metadata column
- Source: CONTEXT.md D-10, D-11. The `IssueListRow` component accepts an optional `productBadge` prop (render prop or `{ color, name }` object); when provided, renders the badge. When absent (single-repo view), renders nothing — backward compatible.

### Per-Repo Error Banner
- Outer: `flex items-start gap-3 px-4 py-3 rounded-md border` with `bg-warning-light border-warning/30` (or use `bg-accent/30 border-border` if warning-light is too loud — see note below)
- Icon: `AlertCircle` from lucide-react, `h-4 w-4 text-warning flex-shrink-0 mt-0.5`
- Text block: `flex-1 min-w-0`
  - Repo name line: `text-sm font-medium text-foreground` e.g. "Acme API"
  - Error description: `text-xs text-muted-foreground` e.g. "Could not load issues" or "Rate limited, retry in 42s"
- Actions: `flex items-center gap-2 flex-shrink-0`
  - Retry: `<Button variant="outline" size="sm">Retry load</Button>`
  - Dismiss: `<Button variant="ghost" size="icon" className="h-6 w-6"><X className="h-3 w-3" /></Button>`
- Multiple banners: wrapped in `<div className="space-y-2 px-4 py-2">` — stacked, not merged
- **Note on banner color:** Use `bg-warning/10 border-warning/30` for rate-limit errors (matches existing `Badge variant="warning"` pattern). Use `bg-destructive/10 border-destructive/30` for hard failures (non-rate-limit errors). This matches the existing badge variant color vocabulary.
- Source: CONTEXT.md D-12, D-13, D-14, D-15

### Sidebar "All Issues" NavLink
- Icon: `Inbox` from lucide-react (represents aggregated inbox — consistent with existing `LayoutDashboard`, `Settings` pattern; more specific than `GitBranch` which is already used in empty states)
- Position: between the "All Products" NavLink and the `ScrollArea` (product list)
- Class: same as "All Products" NavLink — `flex items-center gap-2 px-3 py-2 text-sm transition-colors hover:bg-accent/50` with active state `bg-accent text-accent-foreground font-medium`
- Collapsed state: icon only, no label — same behavior as other nav items
- Source: CONTEXT.md D-01, D-02

### Loading State
- Show `IssueSkeletonRow` (reused from Phase 2) — 8 rows — while any `useQueries()` result has `isLoading: true`
- Once ALL queries have resolved (success or error), stop showing skeletons and show results + banners
- Source: CONTEXT.md (Claude's Discretion — loading state)

## Interaction Patterns

### State Toggle (Open / Closed)
- Two-button group: `open` and `closed` — same pattern as Phase 2 `IssuesFilterBar`
- Active state: `bg-primary text-primary-foreground` (filled button style)
- Inactive state: `variant="outline"`
- URL param: `?state=open` (default) / `?state=closed`

### Keyword Search
- `<Input>` component with placeholder per i18n key
- Client-side filter — no debounce needed (instant, same as Phase 2)
- URL param: `?q=keyword`

### Row Selection
- Click row → opens `IssueDetailPanel` (slide-in from right)
- Selected row: `bg-accent/50 border-l-2 border-primary` — identical to Phase 2

### Retry Banner Interaction
- "Retry load" button calls `refetch()` on the specific failed query (per-repo, not global refetch)
- "Dismiss" (×) hides the banner for that repo — local component state (`dismissedRepos: Set<string>`)
- Dismissed banners stay hidden for the session; a full page refresh brings them back
- If a dismissed repo's retry eventually succeeds (e.g., after manual retry via another means), the banner naturally disappears when `isError` becomes false

### URL State
- Route: `/issues`
- Query params: `state` (`open` | `closed`, default `open`), `q` (search keyword, default empty)
- Pattern matches Phase 2 (CONTEXT.md D-08)

## Filter Bar Differences from Phase 2

Phase 4's filter bar is a simplified variant — no label picker, no assignee picker.

| Control | Phase 2 | Phase 4 |
|---------|---------|---------|
| State toggle | Yes | Yes |
| Keyword search | Yes | Yes |
| Labels multi-select | Yes | **Removed** (CONTEXT.md D-07) |
| Assignee picker | Yes | **Removed** (CONTEXT.md D-07) |
| Reset Filters button | Yes | Yes (resets state + clears search) |

The filter bar for `AllIssuesView` can either reuse `IssuesFilterBar` with props to hide labels/assignee, or be a new lightweight inline component. Either approach is valid — prefer the simpler one.

## Accessibility Notes

- Error banners: use `role="alert"` so screen readers announce them when they appear
- Dismiss button: include `aria-label` using `issues:allIssues.error.dismiss` key (interpolated with repo name)
- Product badge dot: decorative — `aria-hidden="true"` on the dot span; product name label provides the accessible text
- Row `onClick`: wrap in `<div role="button" tabIndex={0}>` or ensure keyboard activation via `onKeyDown` handler (matches Phase 2 pattern)
- Filter bar search input: `aria-label` from i18n key `issues:allIssues.searchPlaceholder`
