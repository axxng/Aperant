**Verification steps:**

1. **Note section placement (NOTES-01 / D-01)**
   - Log in (GitHub OAuth mock — click "Sign in with GitHub")
   - Navigate to any product's issues list
   - Click any issue to open the detail panel
   - Confirm: a textarea labeled "Add a note" is visible BETWEEN the triage row (Triaged toggle + Priority selector) and the labels/assignees/date metadata section

   - Confirm: "Post Note" button becomes ENABLED

3. **Success feedback (NOTES-01, NOTES-03 / D-05)**
   - With text in the textarea, click "Post Note"
   - Confirm: button shows "Sent" with a checkmark icon for approximately 2 seconds, then resets to "Post Note"
   - Confirm: a success toast notification "Note posted to GitHub" appears
   - Confirm: the textarea clears after posting

4. **Idempotency guard (NOTES-02 / D-03)**
   - Navigate away from the issue and back (or refresh the page)
   - Open the same issue again
   - Type any text and click "Post Note" again
   - Confirm: only ONE comment was created (the server returns `{ alreadyPosted: true }` on retry; the UI shows the same success UX — textarea clears, "Sent" state, success toast — NOT an error)

   - Attempt to post a note
   - Confirm: error toast "Could not post note. Try again." appears
   - Confirm: textarea text is PRESERVED (not cleared) so user can retry

6. **Per-user token (D-04)**
   - The note comment on GitHub is attributed to the logged-in user's account (not a shared PAT)
