## Decisions Made

- `vi.doMock` (non-hoisted) is the correct pattern when env vars must be set before the mock factory runs — `vi.mock` hoisting means the factory captures env state at file-load time, not at test-run time
- `vi.resetModules()` at the START of each test (not afterEach) ensures the module singleton is cleared before re-importing with different env vars
- The security gate is `=== 'true'` exact string match: 'True', '1', 'yes', 'TRUE' all fall through to the Turso path — satisfying T-04.2-02-01 (Elevation of Privilege mitigation)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed client.test.ts vi.mock + resetModules isolation pattern**
- **Found during:** Task 1 (RED verification / GREEN implementation)
- **Issue:** The original `client.test.ts` from plan 04.2-01 used `vi.mock()` (hoisted) with `vi.resetModules()` in `afterEach`. For MOCK-01 (the first test), no prior `resetModules()` had run, so `import('./client.js')` returned the module cached at test-file initialization time — before `process.env.MOCK_SERVICES` was set. This caused MOCK-01 to always use the Turso path with undefined URL.
- **Fix:** Replaced `vi.mock()` with `vi.doMock()` (non-hoisted) and moved `vi.resetModules()` to the start of each test body. Each test now: (1) resets module registry, (2) sets env, (3) registers mock via `vi.doMock`, (4) dynamically imports fresh module.
- **Files modified:** `apps/web/api/_lib/db/client.test.ts`
- **Commit:** `d1457b5d`

**2. [Rule 3 - Blocking] Symlinked node_modules into worktree apps/web**
- **Found during:** Task 1 (test execution)

- **Fix:** Created symlink: `ln -s /Users/ivanfoong/repos/dxd/Currents/apps/web/node_modules /Users/ivanfoong/repos/dxd/Currents/.claude/worktrees/agent-ad8c930e/apps/web/node_modules`
- **Files modified:** None (filesystem symlink only)
