## Layout Contract

### Note Section Placement (D-01, source: CONTEXT.md)

The note section inserts **between the triage controls row and the meta divider** (labels/assignees/date). Uses the same `space-y-4` rhythm as the rest of the panel.

```
[Panel header: issue state badge + number + close button]
[Issue title]

[ClosedIssueWarning — conditional, role="alert"]
[Triage row: Triaged toggle | Priority selector]

──────────  (border-t border-border)

[Note section label: "Add a note" — text-xs text-muted-foreground font-medium]
[Textarea — rows=4, placeholder="Write a note to post as a GitHub comment…", resize-none]
[Post Note button — right-aligned, default size, primary variant]
[  → disabled when: textarea is empty OR mutation is pending  ]
[  → transitions to: "Sent" (success variant, CheckCircle2 icon) for 2s on success  ]

──────────  (existing divider)

[Meta: labels / assignees / date / View on GitHub]

──────────  (existing divider)

[Markdown body]
```

### Button layout: right-aligned

Post Note button: `className="self-end"` inside a `flex flex-col gap-2` wrapper for the note section, or use `flex justify-end` on a wrapper row.

## Interaction Contract

### Textarea state machine

| State | Visual | Condition |
|-------|--------|-----------|
| Empty | Placeholder text visible, button disabled (`disabled:opacity-50`) | `noteText.trim() === ''` |
| Filled | Normal border, button enabled | `noteText.trim().length > 0` |
| Submitting | Textarea and button both disabled | `mutation.isPending === true` |
| Success | Textarea clears, button shows "Sent" + CheckCircle2 icon (success variant) for 2000ms, then resets to "Post Note" (primary variant) | `mutation.isSuccess` — use `useState` timer reset |
| Error | Textarea preserves text, button resets to "Post Note" (primary variant) | `mutation.isError` — `toastError()` fires |

### Button label transitions

```
idle (empty)     → "Post Note"        [disabled, opacity 50%]
idle (filled)    → "Post Note"        [enabled, primary variant]
submitting       → "Post Note"        [disabled, opacity 50%]  — no spinner
success (+0ms)   → "Sent"             [disabled, success variant, CheckCircle2 icon left]
success (+2000ms)→ "Post Note"        [enabled, primary variant — reset via setTimeout]
error            → "Post Note"        [enabled, primary variant — toast fires separately]
```

No loading spinner inside the button — mutation feedback is implicit via disabled state.

### Toast messages

| Trigger | Type | Copy |
|---------|------|------|
| Successful note post | Success toast | "Note posted to GitHub" |
| Failed note post | Error toast | "Could not post note. Try again." |

Toast calls match Phase 5 pattern: `toast('Note posted to GitHub')` and `toastError('Could not post note. Try again.')`.

### Already-posted idempotency (D-03)

If server returns `{ alreadyPosted: true, commentId }`: treat as success — textarea clears, "Sent" button state fires, success toast shows. The user sees the same success UX regardless of whether this is the first post or a retry. No special UI state for "already posted."

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| Textarea label | `<label htmlFor="note-textarea">{t('notes.sectionLabel')}</label>` — visible label, not aria-label only |
| Button disabled state | Native `disabled` attribute on `<button>` — `aria-disabled` not required when using native disabled |
| Success state announcement | `aria-live="polite"` region wrapping the button or button area — announces "Sent" on state change |
| Keyboard: submit on Ctrl+Enter | Optional: `onKeyDown` handler on textarea — `if (e.ctrlKey && e.key === 'Enter' && !isDisabled) submitNote()` |
| Focus management | After successful post, focus remains on the (now cleared) textarea — no forced focus movement |
