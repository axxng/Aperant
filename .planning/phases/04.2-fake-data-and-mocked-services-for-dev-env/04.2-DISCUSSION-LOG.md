## DB Layer Mock

| Option | Description | Selected |
|--------|-------------|----------|
| Local SQLite file | `file:dev.db` — persists across restarts, migrations run once, survives seed | ✓ |
| In-memory SQLite | `:memory:` — resets on every server restart, clean slate but requires re-seed | |
| Both — file default, memory opt-in | `file:dev.db` by default, `DB_MODE=memory` to override | |

**User's choice:** Local SQLite file — `file:dev.db` via `@libsql/client`

| Gitignore question | Options | Selected |
|--------------------|---------|----------|
| Gitignore dev.db | Each dev seeds their own; no binary blobs in git | ✓ |
| Track a seed-only snapshot | Pre-seeded dev.db committed to repo; merge pain | |

**User's choice:** Gitignore dev.db

## GitHub API Mock

| Option | Description | Selected |
|--------|-------------|----------|
| Fixture JSON files in dev-server.ts | Express middleware intercepts `/api/github/*`; no new deps; easy to edit | ✓ |
| MSW (Mock Service Worker) | HTTP-level mock; adds msw dep; works in browser + Node | |
| Swap githubFetch() at module level | Mock inside application code; invasive | |

**User's choice:** Fixture JSON files in dev-server.ts

**Endpoints selected for mocking:**
- Issues list (per-repo + cross-repo) ✓
- Issue labels ✓
- OAuth flow (GitHub login) ✓
- Triage + products (DB-backed — no GitHub mock needed) ✓

| OAuth mock style | Description | Selected |
|------------------|-------------|----------|
| One-click bypass | Mock callback immediately creates admin user session; no redirect | ✓ |
| Fake OAuth redirect loop | Simulated full redirect loop locally | |
| Pre-set JWT in .env.development | No login step at all | |

**User's choice:** One-click bypass — mock `/api/auth/github/callback` returns seeded admin session
