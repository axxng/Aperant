# Phase 04.1 Plan 03: GitHub API Ingestion Parse-Don't-Validate Summary

**One-liner:** Zod schemas for GitHub API/OAuth responses added to validation.ts; mapGitHubPR and mapGitHubIssue now call schema.parse() on unknown input before field access.

## What Was Built

- **gitHubApiIssueSchema** — Zod schema for GitHub REST API issue response shape; enforces id, number, title, state, user, labels, assignees, timestamps, url fields
- **gitHubApiPRSchema** — Zod schema for GitHub REST API PR response shape; enforces number, title, state, head/base refs, timestamps, html_url
- **oauthTokenResponseSchema** — Zod schema for OAuth token exchange response (access_token + optional error)
- **gitHubUserSchema** — Zod schema for GitHub user API response (id, login, nullable email/name)
- **mapGitHubPR(rawPr: unknown)** — Now calls `gitHubApiPRSchema.parse(rawPr)` as first statement; rejects malformed GitHub PR responses with ZodError at the boundary
- **mapGitHubIssue(owner, repo)(rawIssue: unknown)** — Now calls `gitHubApiIssueSchema.parse(rawIssue)` as first statement; rejects malformed issue responses
- **7 new tests** — 4 for mapGitHubPR/mapGitHubIssue parse behaviour (github.test.ts), 3 for TriageState variant construction (triage.test.ts)

- **Fix:** Changed to `pr.user?.login ?? ''` — fallback to empty string when PR has no user

- **Fix:** Updated return type to `Promise<(TriageRecord & { triageState: TriageState }) | null>`
