## Component Inventory — Phase 7 Additions

These are the new/modified UI elements for this phase. All use existing component primitives.

### 1. Promote Button (`IssueDetailPanel` — new element)

**Location:** After the triage controls row and before the divider, inside `IssueDetailPanel`.

**States:**
| State | Appearance |
|-------|-----------|
| Default (not yet promoted) | `<Button variant="default" size="sm">Promote to Backlog</Button>` with a `BookmarkPlus` (lucide) icon left of label |
| Loading (mutation pending) | `disabled` + `opacity-50` + spinner icon replaces `BookmarkPlus` |
| Already promoted (PROMOTE-03) | Replaced entirely by "View in Backlog" badge — button is NOT shown |
| Duplicate guard blocked (PROMOTE-05) | Toast error (existing `useToast` pattern); button re-enables |

**Markup pattern:**
```tsx
<Button variant="default" size="sm" disabled={promoteMutation.isPending} onClick={handlePromote}>
  <BookmarkPlus className="h-3.5 w-3.5 mr-1.5" />
  {t('promote.promoteButton')}
</Button>
```

### 2. "View in Backlog" Badge (`IssueDetailPanel` — conditional replacement)

**Shown when:** issue already has a linked backlog task (`githubIssueNumber` matches on a `pr_created` or any status task).

**Appearance:** `<Badge variant="success">` with `<ExternalLink>` icon, rendered as an anchor tag (`asChild` + `<a>`) linking to the Kanban task.

```tsx
<Badge variant="success" className="cursor-pointer gap-1 text-xs" asChild>
  <a href={`/tasks/${taskId}`}>
    <ExternalLink className="h-3 w-3" />
    {t('promote.viewInBacklog')}
  </a>
</Badge>
```

### 3. Duplicate Guard Toast

**Trigger:** API returns 409 Conflict when trying to promote an already-promoted issue.

**Appearance:** Uses existing `useToast()` — `toastError(t('promote.duplicateError'))`. No modal or dialog — inline toast only.

### 4. Priority Pre-population (PROMOTE-04)

No new UI element. The `CreateTaskDialog` (or promote API) receives `priority` pre-populated from `triageData.priority`. The promotion is **one-action** (PROMOTE-01) — no dialog is shown. Priority flows silently from triage state to the new task. If `triageData.priority` is null, task is created with no priority set.

## Interaction Contract

### Promote Flow (happy path)

1. User opens `IssueDetailPanel` for an issue that has not been promoted.
2. Promote button is visible below the triage controls row.
3. User clicks "Promote to Backlog".
4. Button enters loading state (disabled + spinner).
5. API `POST /api/tasks` fires with title from issue title, priority from `triageData.priority`, `githubIssueNumber`, `githubIssueUrl`, `githubRepo`, status `backlog`.
6. On success: button is replaced by "View in Backlog" badge (success variant) linking to the new task. Toast success fires.
7. On failure: button re-enables. Toast error fires with actionable copy.

### Already-Promoted State (PROMOTE-03)

When `IssueDetailPanel` opens for an issue that is already linked to a backlog task:
- The promote button is NOT rendered.
- The "View in Backlog" badge is rendered in its place immediately (no loading state needed).
- Badge is a link to the Kanban task (`/` route with task highlighted, or task direct URL if applicable).

### Duplicate Guard (PROMOTE-05)

If the API returns 409 (duplicate promotion):
- Toast error: "This issue is already in the backlog." (see Copywriting Contract)
- Panel re-renders to show "View in Backlog" badge (treat 409 response body as the existing task link).
- No duplicate task is created.

### Animation

- Promote button → "View in Backlog" badge transition: use existing `--animate-fade-in` (0.25s ease-out). No slide animation needed.
- Loading state: no spinner animation beyond existing `disabled:opacity-50` — keep it minimal.
