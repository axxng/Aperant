<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated route → DB lookup | User's JWT provides userId; DB lookup gets their github_token |
| Route → GitHub API | github_token flows server-to-server only; never returned to client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Spoofing | GitHub proxy routes — token resolution | mitigate | `authenticateRequest()` validates JWT before getUserById; token is never user-controlled |
| T-03-11 | Information Disclosure | github_token in GitHub API responses | accept | Responses from GitHub API are proxied to the requesting authenticated user only; no cross-user data exposure |
| T-03-12 | Denial of Service | 403 on missing github_token | accept | Users without github_token (created via admin panel) receive a clear 403 message and must complete OAuth login |
</threat_model>
